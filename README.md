# Supplementary Material: Agent Memory Without Ingest-Time Models

Code, frozen protocols, and per-question results for the paper *Agent Memory Without Ingest-Time Models: Summaries Are Indexes, and Trajectories Already Contain One*.

The material covers every number reported in the paper. It does not redistribute the LongMemEval-V2 benchmark (trajectories, screenshots, questions or gold answers); results refer to questions and trajectories by their benchmark ids, and question text and gold answers were removed from the per-question result files. The synthetic questions in `results/synthetic_selection/` were generated by us and are included in full.

## Layout

```
code/
  common/              shared memory construction, reader client, deterministic scoring
  locate_vs_read/      raw / structure / summary memories, summary-located reading, lazy routes (Section 3)
  trajindex/           TrajIndex units, routing and compact reading; synthetic selection; final test (Sections 4-6)
  reference_pipeline/  runner for the benchmark's AgentRunbook-R summary pool (enterprise and web)
  judge/               blind LLM judging of the flawed-premise questions (Message Batches API)
protocols/             protocols frozen before each test, file hashes, question splits (ids only)
results/               per-question scores, analyses, synthetic questions, judge labels, ingest costs
```

## Order of experiments and use of questions

The protocols in `protocols/` were frozen, with the listed file hashes, before the runs they govern:

1. `CONFIRMATION_PROTOCOL.md`: enterprise held-out run of the Section 3 memories and the TrajIndex prototype.
2. `WEB_PROTOCOL_ADDENDUM.md`: the same arms on the 153 web questions, after building the web summary pool.
3. `IMPROVE_PROTOCOL.md`: three CPU-only routing variants, selected on development questions only. None beat the prototype, so no held-out run followed.
4. `SELECTION.md`: configuration chosen on 299 synthetic questions, then run once on the real questions.

The 258 deterministic held-out questions were scored twice: once in steps 1-2 and once in step 4. The prototype's result in steps 1-2 motivated further development, but no configuration was chosen on these questions. The 128 LLM-judged questions were added after the step-4 deterministic result and were scored once.

## Reproducing

### Requirements

- Python 3.10 or later
- `transformers`, used for the Qwen3.5-9B tokenizer that counts budget tokens
- `numpy`
- `vllm` 0.22, for serving the models
- `anthropic`, for judging only

Models: Qwen3.5-9B (reader, synthetic-question generator, controller of the reference pipeline) and Qwen3-Embedding-0.6B (reference pipeline embeddings), served as OpenAI-compatible endpoints on `127.0.0.1:8122` (and `8123`) and `127.0.0.1:8119`.

### Workspace

All scripts read from and write to a directory named `workspace/` (relative to the working directory). Place there:

- `workspace/LongMemEval-V2/`: the official benchmark code at commit `2cc8c540bdb87fe6761629b585e727e1c4704520`. Its evaluation module provides the scorer and the judge prompts.
- `workspace/questions.jsonl`, `workspace/trajectories.jsonl`, `workspace/lme_v2_small.json`: benchmark files.
- `workspace/data/`: benchmark screenshots, used only by the reference pipeline.
- `workspace/models/Qwen3.5-9B`, `workspace/models/Qwen3-Embedding-0.6B`.

Paths can be redirected with the environment variables the scripts read:

| Variable | Meaning |
|---|---|
| `FEAS_OUT` | output directory |
| `FEAS_POOL` | reference summary pool |
| `FEAS_STATES` | JSONL of states, one object per state with `trajectory_id`, `state_index`, `url`, `action`, `accessibility_tree` |
| `FEAS_DOMAIN` | `enterprise` or `web` |
| `CONF_SPLIT` | question-split file |

### Steps

1. **Reference summary pool.** Use `code/reference_pipeline/official_anchor.py --stage build` (enterprise) and `build_web_pool.py --shard k --port p` (web). Unchanged official builder; only endpoints, logging and scheduling are adapted.
2. **Memories of Section 3.** Run `code/locate_vs_read/build_confirm.py`, `build_index_route.py` and `build_routes.py` to build reader contexts. Then `code/common/run_reader.py` answers and `score_feasibility.py` scores. Analyses: `confirm_analysis.py`, `pooled_analysis.py`.
3. **TrajIndex.** `code/trajindex/zc_index.py` builds units, routes and reads; it needs no model. `synth_questions.py` generates the synthetic set. `tune.py proxy | contexts | read` runs the CPU screen, builds contexts and answers. `score_synth.py` scores; `final_analysis.py` reproduces the held-out comparison.
4. **Judging.** `code/judge/export_judge.py` exports blinded items. `judge_batch.py submit/collect` judges through the Message Batches API: set `ANTHROPIC_API_KEY`, `ANTHROPIC_WORKSPACE_ID` and `JUDGE_MODEL=claude-opus-5-5`. `judge_pipeline.py analyze --tag full --rejudge rejudge_sonnet` unblinds and pools.

Statistics everywhere: paired bootstrap over questions, stratified by domain (and by scoring set when pooled), 10,000 resamples, seed 0, 95% percentile intervals, non-inferiority margin of 5 points.
